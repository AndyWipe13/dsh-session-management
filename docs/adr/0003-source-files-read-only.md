# ADR-0003：第三方源文件永远只读，删除/清理只作用于 DSH 侧

- 状态：accepted
- 日期：2026-08-30

## 背景

插件需要扫描 Claude Code（`~/.claude/projects/**`）与 Codex（`~/.codex/sessions/**`、`~/.codex/archived_sessions/**`）的会话文件。删除与批量清理是核心功能，存在把"清理"误扩展到源文件的风险：一旦删除第三方源文件，会破坏 Claude Code / Codex 自己的会话列表与恢复能力，且不可恢复。

## 决策

1. **源文件只读**：对第三方目录只做扫描、读取、解析、hash/stat。插件代码路径中不出现任何指向第三方目录的写/删/移动操作；删除实现的目标路径只能来自 DSH 侧（`sessionPersistence.locate()` 或导入 manifest 反向索引）。
2. **清理作用域**：批量清理规则只匹配 DSH 侧会话（原生 + 已导入副本）。UI 与工具文案明确"不影响 Claude Code / Codex 中的原会话"。
3. **永不提供"连带删除源文件"选项**：即使加危险开关也不做——违反底线，且违背需求方在 grilling 中的明确确认。
4. **测试护栏**：回归测试断言一次完整"导入 → 删除 → 清理"流程后，被扫描的第三方源文件字节不变（mtime 亦不得变化）。

## 备选方案

- **提供可选连带删除**：需求方明确否决；破坏其他 agent 的数据完整性。否决。
- **删除导入副本时反向删除源文件**：同上，否决。

## 后果

- 正面：第三方 agent 的数据完整性得到绝对保证，用户可放心使用批量清理。
- 负面：用户若想彻底清理磁盘上的第三方会话，必须回到 Claude Code / Codex 自己的会话管理里做——这是刻意的边界，不是缺陷。
